# 多会话连接验证

2026-11-14，服务端 v0.7.1，插件 v0.7.0，Blockbench 5.2.2，Node 24.14.0，Windows。

## 自动化

`npm run check`：严格 TypeScript、213 项测试和构建通过。

- 两个共享桥接客户端连接同一插件，交错创建/修改/查询工程，目标与内容保持各自正确。
- 从客户端关闭不影响主服务；主客户端关闭后存活客户端重新监听，插件自动重连，原管理权限保留。
- 错误密钥与不同工作目录拒绝；旧服务不支持多会话协议时明确握手失败，不抢占或杀进程。
- 已取消调用不执行；排队中的取消不在稍后补执行；已关闭目标报 NOT_FOUND，不操作其他活动标签。
- 超时修改标记不确定，查询确认仅执行一次，不自动重放。
- 官方 SDK legacy / modern 测试均增加第二个独立 stdio 子进程，完成 tools/list、双目标创建与并发查询；无需换端口或复制配置。

## 真实宿主

`npm run smoke:multi-session -- --workspace <工作目录>` 通过。测试先核对并停止本仓库旧版独占服务，再启动新版；未重载 Blockbench 插件。

两个独立官方 SDK 客户端注册 29 个工具，连接同一插件；创建 A/B 两个测试标签，并发分别创建 only_A / only_B 方块；各自 get_project_state 返回正确工程与唯一方块，再通过官方接口保存两个 bbmodel。

关闭 A 后，日志确认 B 接管原端口；插件自动重连，B 仍可查询原工程。随后第三个客户端加入并选择 A，B 查询仍返回 B。原始证据位于忽略的 `.tmp/multi-session-1794679076263/evidence.json`，不提交测试资产、密钥或原始日志。

## 边界

- SDK 双客户端验证等价的独立 stdio 通路；Codex 既有聊天的旧初始化失败缓存仍需通过重启 MCP / 客户端清除，不能声称现有聊天已自动热更新。
- 各会话共享同一工作目录授权及插件管理权限，不是互不信任用户之间的隔离。对同一工程的语义冲突须由调用者协调。
- 当前目标保留在 stdio 进程内，进程彻底重启后应通过 list_projects/select_project 重新选择。
- 故障接管期间插件可能尚未重连，返回 NOT_CONNECTED；不重放已经发送的修改。手动关闭工程、锁定标签或原生编辑事务仍可导致预期错误。
- 不支持将不同工作目录的独立配置强行合并到同一端口；不提供任意代码执行接口。
