# 第七阶段真实宿主测试

## 自动调用部分

1. `npm run check` 构建 v0.7.0。重载桌面插件，停止同端口的客户端 MCP 服务。
2. 运行 `npm run smoke:modeling -- --workspace <仓库绝对路径> --wait-seconds 120`。插件 Connect 相同工作目录，或等待已连接插件自动重连。
3. 脚本用官方 SDK 启动 stdio Server，检查全部 29 个工具，创建独立测试工程与第二个标签。不会修改用户原有模型。
4. 核查 0.5 × 0.5 × 0.3 铆钉的 6 个退化面，逐面设置后诊断清零。修改坐标保留 ID、父级、UV 和贴图绑定。
5. 门框与门扇在默认姿态不相交；动画 0/0.5/1 秒采样应在中间及 90° 姿态报相交，最终投影重叠约 1。采样前后的工程状态、动画关键帧应一致。
6. 官方保存 `.bbmodel`、导出 `.geo.json`，渲染关闭/打开两张 PNG，像素内容应不同且非空；切换第二标签再返回，应保持完整状态。

补测 UV 模式转换：创建 mirror_uv:true 方块，逐面六面均设 [8,8,12,12]，再 set_cube_uv 省略 mirror_uv，结果应仍为 true。反向案例：先明确 mirror_uv:false，再逐面 east=[8,8,12,12]、west=[1,8,4,12]，重新切回 Box UV 省略 mirror_uv，结果仍为 false。这两种情况与原生自动推断结果相反，确保工具保留参数约定。

自动记录输出在 `.tmp/modeling-smoke-*/`，不提交原始日志、PNG 或测试 bbmodel。脚本关闭后其独立 Server 停止，恢复日常使用需重启客户端 MCP 服务。

## 原生 Undo/Redo 与重新打开

保持同一个插件管理会话和测试服务：

1. 在测试标签调用 `set_face_uv` 将铆钉六面改为 [16,16,20,20]；再用 `update_cubes` 改名称和 X 坐标。先记录修改前后 get_project_state / get_cube_uv。
2. 原生撤销两次：核对六面 UV、rotation、名称、坐标、元素 ID、父级与纹理绑定均恢复。不要只检查数量。
3. 原生重做两次：上述字段应与修改后完全一致。使用官方 `save_project` 保存。
4. 关闭该标签，再通过文件菜单打开保存的 bbmodel。查询工程、逐面 UV、动画及诊断；允许工程 UUID 变化，几何、元素/骨骼/贴图 ID、UV、动画关键帧保持。
5. 重新打开的工程 `managed:false`，读取诊断可用，不能因 select_project 获得编辑权限。碰撞采样结果保持。

若出现失败，记录真实错误、阶段和恢复情况；替身测试不能替代此验收。本轮无 Computer Use 授权时由用户操作原生快捷键和重新打开。
