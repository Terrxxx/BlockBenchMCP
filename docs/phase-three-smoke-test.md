# 第三阶段手动冒烟测试

先运行 `npm run check`，重载 `dist/plugin/blockbench_ai_mcp.js`，重启 Codex 的 MCP Server，确认能列出 16 个工具，再从 Blockbench Tools → Blockbench AI MCP: Connect 连接工作目录。同一端口只能运行一个服务器。插件重新加载后先新建测试工程；已有标签只可查询。

按 [JSON 示例](../examples/phase-three-tool-calls.json) 顺序调用。占位符必须替换为前一步返回的真实 ID，不能照抄；使用唯一工程名和未占用的保存路径。

1. 新建 Bedrock 工程，建立 root → arm 两个骨骼，并分别放入 body 与 arm 方块。
2. 创建 2 秒 loop 动画；一次写入三个通道在 0、1、2 秒的共 9 帧。查询每个 UUID、时间、数值和插值。原生数值可能以字符串返回，这是正常的。
3. 在 1 秒定点预览：手臂旋转、根骨骼上移、手臂伸长；时间线应暂停。更新片段名称、长度 2.5、hold、snapping 30。
4. 同一批更新 arm 的 1 秒旋转为 -65 度，并新增 root 的 0.12345 秒位移。检查原帧 UUID 不变、新帧时间不吸附，视图保持动画姿态。
5. 删除新增位移帧与 arm 的 2 秒缩放帧；查询应剩余 8 帧。记录完整查询结果作为基线。
6. 在模型视图中操作正常编辑菜单或 Ctrl+Z，连续撤销 5 次（删除、upsert、元数据、首批帧、创建片段）。查询应无动画。连续重做 5 次，查询必须与基线一致，尤其检查 animator 及关键帧 UUID。不要在输入框内按快捷键，以免撤销文本。
7. 分别发送越界时间、缩短长度、重名、未知帧 ID、表达式向量、越界预览、近邻时间冲突。失败后查询应与基线一致；批次中前面的合法项也不得残留。
8. `save_project` 保存为工作目录内新的 `.bbmodel`；默认不覆盖文件。通过 Blockbench 关闭这个已保存标签，再用“文件 → 打开”重开。
9. `get_project_state` 取得新的工程 UUID，再以新 UUID 和原动画 UUID 调用 `get_animation_state`。比对骨骼层级、方块、片段属性及全部帧。重开后 `managed:false` 是预期；此阶段不接管重开的工程。

动画面板中的 “Unsaved” 表示没有单独保存外部动画 JSON；本测试仅保存 bbmodel。若调用超时或断线，先恢复连接并查询，不自动重试修改；保存结果不确定时先核对目标文件。系统文件对话框可能暂时阻塞宿主查询，关闭对话框后再读取。

记录测试环境、工具结果、失败原因及是否真正通过。不要把自动化替身测试等同于真实 Blockbench 验收，也不要把独立 SDK 调用写成 Codex 当前聊天的原生调用。
