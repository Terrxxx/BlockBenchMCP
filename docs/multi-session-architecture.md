# 多会话桥接

2026-11-14：原 stdio 进程各自绑定同一端口，第二个进程会在 MCP 初始化前因 EADDRINUSE 退出。

依据 [Node net.listen](https://nodejs.org/api/net.html#serverlisten) 的独占监听/错误语义与 [ws API](https://github.com/websockets/ws/blob/master/doc/ws.md)，采用同端口主进程选举：第一个 stdio 持有桥接，其余 stdio 通过带工作目录和密钥认证的本地 WebSocket 转发白名单调用。插件协议 v7 不变，不新增宿主任意执行能力，不产生常驻后台进程或修改全局配置。

- 本地客户端使用独立 client_hello / client_call / client_result 消息，不可冒充插件回复；限 16 个客户端、32 个排队调用、1 MiB 消息。
- 每条客户端连接记录最多 4096 个请求 ID；超出后关闭并要求后续调用重新连接，防止去重记录无界增长，已发送请求不会自动重放。
- 所有客户端（含主进程自己的 stdio）共用串行操作队列。指定 project_id 的调用在同一队列任务内先选择工程再执行；每个 stdio 保存自己的最后目标 ID，get_project_state 恢复该目标。list_projects 仍列出全局状态。关闭的目标必须报错，不能落入其他标签。
- 插件已有管理会话权限仍为最终权限边界。认证过的同工作目录会话可协作编辑其托管项目；不自动接管手动打开的项目。手动 GUI 改标签时仍由插件 project_id 检查防止误改。
- 主 stdio 退出时，其他客户端下次调用重新选举/连接；未发出的请求可等待连接，已发出的请求绝不自动重放。插件自动重连，尚未重连时返回 NOT_CONNECTED。退出一个从客户端不会关闭主服务。
- RPC 超时/断线返回 outcome_unknown；只读查询不标记模型写入不确定。截止时间覆盖排队，过期任务不得再执行。取消通过连接请求 ID 转发，不能取消其他客户端请求。
- 旧服务占用端口且不支持客户端协议时明确报告不兼容，禁止杀进程或修改端口绕过。

验证：两个官方 SDK stdio 客户端共端口、双目标交错、从客户端退出、主客户端退出/接管、错误认证、过期/取消及无重放；真实 Blockbench 双客户端创建/查询/保存，记录未执行的宿主项目。

服务端版本 v0.7.1，插件继续使用 v0.7.0 / bridge 7，无须重载插件。第一次升级必须退出旧的独占服务进程并重启客户端 MCP；以后的多个新版进程可正常共存。
